## Metadata

All 30 source images carry metadata that was flagged as sensitive (EXIF, JPEG/JFIF density fields,
and for ten of them a full RetCam device block). **All 30 exported images carry none.**

The export does not copy or strip metadata from the source file. It decodes the image, rebuilds a
fresh `PIL.Image` from the pixel array, and writes that. Nothing from the source container can
survive because nothing from the source container is reused.

| quantity | value |
|---|---|
| source images with flagged metadata | 30 / 30 |
| exported images with any metadata at all | 0 / 30 |
| dimension mismatches | 0 |
| pixel mismatches against the decoded source | 0 |
| images re-encoded or resized | 0 |

`metadata_audit.csv` in the package records this per image. It lists the study ID, the output file,
the source and output dimensions, the metadata keys found in the source, and the two preservation
flags. It deliberately contains **no** source, label, split, group or original path.

## Filename leakage

Matching is on word boundaries, not raw substrings. A substring test rejects
`example_disc_correct.png`, because `exam` sits inside `example`; that is a false positive and was
fixed rather than worked around.

Directory names **below the package root** are checked as well as file names, because a leaky
folder is as revealing as a leaky file. Directory parts **above** the root are excluded, otherwise
the parent folder `expert_validation` matches on the word `validation`.

Every packaged file name is one of: a blinded study ID, a fixed deliverable name, a schematic
example name, or `README.txt` inside one of the three output folders.

## What the package deliberately does not contain

- `blinding_key.csv`, `manifest_blinded.csv`, `sampling_summary.csv`, `MANIFEST_SHA256.txt`
- any original path, source name, label, split, group ID or geometry
- automatic vessel or disc masks, model predictions, probabilities, Grad-CAM
- any internal result, threshold, acceptance target or analysis output

## The annotation manual

The manual comes from the frozen `expert_validation/ANNOTATION_MANUAL.md`. Its body is shipped
**unedited**. It was written for the full 120-image study, so the pilot PDF carries a short header
stating that this package contains 30 images and that, where the text says 120, the reader should
read 30. Nothing in the procedure itself was rewritten.

The manual legitimately discusses ROP, Plus, Pre-Plus, arteries, veins and annotation rules. Those
are clinical concepts, not per-image information, and are expected in a clinician-facing document.

The five illustrations the manual refers to are **drawn schematically at build time**. No study
image and no external dataset image is used, so there is nothing to license and nothing that could
leak.

## Reproducing

```bash
python expert_validation/build_pilot_package.py
python scripts/validate_expert_pilot_package.py \
    --package expert_validation/package_build/expert_pilot30_v1.0 \
    --key expert_validation/blinding_key.csv
```
